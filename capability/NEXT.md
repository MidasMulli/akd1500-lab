# Next discriminators after native execution qualification

The current physical campaigns are closed. Native hardware capability and a
useful CPU advantage remain separate endpoints; a CPU emulator is a correctness
control, not a reason to dismiss architectural differences.

1. **Broaden the native arithmetic basis.** The current binary 1×1 task gives
   the CPU an effective packed-popcount implementation. Next qualify documented
   signed low-bit weights, supported activation precisions and spatial
   convolution/reuse. Start with ordinary compiler/virtual checks, then a small
   native exact-output gate and optimized CPU integer/vector controls. Reject
   unsupported formats rather than silently changing precision or mathematics.
   Only then scale channels, spatial extent, residency and active-event density.
2. **Separate native work from host transport.** Current ingress is dense. Audit
   the actual supported sparse-input/DMA contract, then compare identical events,
   outputs and whole-host work under separately frozen transport treatments.
   The sleep test establishes blocked-worker execution, not interrupt-driven
   completion or a free end-to-end input path. SPI feasibility depends on the
   actual board/interface, not the chip family's marketing description.
3. **Measure useful offload and energy.** Match accuracy, retention, event rate,
   deadlines and complete input/output work against an effective CPU solution.
   Released-interval CPU reduction alone excludes staging/drain. Qualify a
   calibrated card/host power measurement boundary before advertising energy.
4. **Enumerate learning execution constraints.** The installed runtime's
   single-pass allocation ceiling is 128 slots; that is not a silicon maximum.
   The held-ring technique needs a spare slot. The failed 128-event stage remains
   failed. Any new ring/interrupt/teacher-stream experiment needs a prospective
   protocol and must establish state/order correctness before throughput claims.
   Same-job updates and one common teacher do not prove independently driven
   simultaneous learning streams.
5. **Keep retention and recovery as distinct studies.** Repeated dictionaries,
   record recruitment, saturation, hidden selector state and restart durability
   remain useful questions, but another association demo does not substitute for
   arithmetic/transport/energy differentiation. Visible RAM is not complete
   resumed-learning state; retain full-prefix replay until separately qualified.

An arbitrary learning-instruction loader or firmware replacement interface is
still not established in the reviewed sources. Native behavior is measured;
whether the update engine is fixed logic or internal microcode remains open.
Do not turn either uncertainty into a claim of physical impossibility.

The promised practical-advantage X-post gate remains unmet. The current artifacts
support an honest native-capability research update, with the CPU result and
failed stage visible, not a performance or energy victory claim.
