## Mechanism and host boundary

Seven sequential FNP3s: signed source-role encoder; source teacher; signed native
teacher/student error comparison; binary outcome-0 feature encoder; student-0
memory; signed opposite-valence bridge; student-1 memory with fixed readout helpers.
Each learning bank uses 512 inputs and eight plastic records. Teacher/student-0 use
64 records each; student-1 uses128. Helpers are fixed records, not extra learners.
All three are configured with two hardware classes; student plastic records lie in
class0 only. Bank identity encodes valence. Constant class0 therefore suffices during
every transfer, regardless of the learned source prediction.

The host supplies raw four-bit cues and fixed role clocks. External actual labels
reach the source only during grounding, when both students are disabled. Transfer
consumes the prior native query-output pointer, with only role bytes changed; the
host supplies constant label0 and no outcome bytes. Source learning is disabled,
both student banks share the same enabled clock. Fixed native predicates and codes
decide which valence bank receives full positive features versus a one-bit sentinel
replacement. The qualified native winner/swap primitive selects and updates records.
The error rule, role schedule, valence split and encoding are engineered.

Query-only carrier fields are inactive on every transfer. Plastic support must stay
inside the first110 coded positions; every helper record stays unchanged. A source
with no answer must not teach either student. The teacher-silent exam masks only the
source plastic cue code while independently relaying the raw key through its fixed
helpers. Source returned class bits and derived plastic potentials must be zero;
students still query their own native stored connections. The source NPU remains
clocked as part of the pipeline: this is answer-path silence, not power gating.
