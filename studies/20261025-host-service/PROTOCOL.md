# Host cost of resident native learning

Direct operator go on October 25 authorizes the proposed staged campaign:
reduce host involvement on the verified native graph; check outputs and learning
memory before expansion toward a busy-Nano comparison. This study has its own
finite authority and never reopens earlier campaigns. Scientific cutoff
18:04:30 UTC; hard stop 18:06:30 UTC. At most 80 device sessions / 8192 forwards,
120 seconds per owned cell, shared research lock and free-device admission.
No clocks, voltage, firmware, kernel or unrelated services may be changed.

## Frozen arithmetic and input stream

Reuse the independent 32/64-pixel RGB -> HRC32 -> CNP512 -> projection8 ->
128-record binary native learner from the reference/scale study. The 64-event
sequence remains eight prefix queries, 32 labelled teaching events, 16 repeated
queries and eight novel queries. Learning/frozen arms, seeds 107501, 107601,
107701. No prediction quality, natural-image accuracy or inference-skipping
claim follows from these synthetic characterization inputs.

Potential and activated-output variants use identical inputs, front weights,
features and initial learner connection masks/learning metadata. The compact
contract is 128 binary responses, potential >24. Inference metadata may differ;
compare complete RAM against each exact CPU replica, and compare learning fields
across output variants before making equivalence claims. Never call compact
responses equivalent to returning all potentials for arbitrary consumers.

## Stages and admission gates

1. Virtual compiler/independent integer feature checks. All five CPU paths
   (NEON dense, zero-skipping, OpenMP4, OpenBLAS1/4) must agree on every output
   and complete memory boundary. These controls include all image processing,
   feature packing and learning; fixed-weight packing remains setup.
2. Potential-output baseline, side32 primary seed: eight-query native smoke,
   then 64-event learning and frozen runs. Every returned value and captured
   full RAM boundary must match independent reconstruction; fixed CNP packets
   must remain unchanged. Then side64 and binary-output gates, in that order.
3. On passing side64, vary only transport/completion/queue settings. Profiles
   are DMA-read+MMIO-write and DMA-read+DMA-write; sleep intervals 0/100/500us;
   batch 1 or 8 (nine ring slots for eight queued inputs). Preserve phase
   boundaries, event order and labels. First qualify each new setting, then
   examine its timing. Native batch8 validates every output and full RAM at each
   batch boundary; it cannot claim per-event native RAM observations.
4. Replicate passing Pareto candidates (at most two, selected only from the
   primary screen) on the remaining two seeds and three rotated repetitions.
   Choose candidates by measured wall latency and caller CPU jointly; do not
   silently compare the chip against a weaker CPU control. Initial screen
   timings are descriptive and distinct from confirmation repetitions.
5. A separate prospectively recorded busy-host amendment may run only after
   the above correctness gates pass. It must freeze foreground model/source,
   workload, arrival rate, background arms, order, duration and failure rules
   before measured contention. It may not modify the deployed model/server.
   Final output/RAM checking can be deferred outside common measurement windows
   only after the full-audit configuration passes. Report all such differences.

A numerical mismatch stops expansion. Preserve raw partial arrays, failed owner
and source versions. Routine harness repairs require a new recorded source freeze
and requalification before expansion; no silent retry or dropped seeds.

## Measurement and claim boundaries

Include mode change, input copy, enqueue, wait/fetch and consumer output copy in
operational wall/process CPU time. Save component times, polls and transport
bytes/calls; verification/readback/file serialization stay outside that interval.
Batch cost is measured per batch; amortized per-image cost is derived, not a
measurement of each image's readiness latency. CPU time includes all process
threads. It is not whole-host CPU consumption or electrical energy.

Full-audit cells compute the independent reference outside operational timing.
Those observers disturb the surrounding workload, so contention must use a
separate admitted operational window with audits outside that window.

For every owned cell preserve source/binary/fixture hashes, affinity, environment,
wall/process timing arrays, exact outputs, complete RAM boundaries, fixed packet
before/after and device release. No assembled power rig or energy advantage is
implied. A CPU-time/latency tradeoff is not automatically a practical advantage.
Visuals must use recorded responses/connection changes and identify schematic
geometry, time expansion and synthetic inputs. Only measured benefits qualify
as the proposed practical-advantage milestone.
