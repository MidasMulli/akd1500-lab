# Native memory admission — prospective staged experiment

User authorization: “Agree, go. ... targeting capabilities beyond what brainchip
provides as baseline ... beyond what is obvious and provided by the company.”

Target: a native management group controls which observations reach a second
learning bank. Both banks receive the same externally observed outcome labels;
Nano never interprets a manager response into a selected bank or record command.
Predictions must precede outcome delivery. A finite fixed-budget study follows
only after native admission and read-only retrieval qualify.

## Beyond-baseline boundary

BrainChip already supplies binary-input/weight learning, competition, class-label
groups and a final trainable classifier. We do not invent those primitives. Our
candidate combines two intermediate resident plastic banks, native data-dependent
write admission, a native carried-input path, and prospective prediction with
retention under capacity pressure. The management rule (admit consecutively
repeated keys) and representation are deliberately designed, not learned. No
claim that repeat filtering itself is a new algorithm, global first, CPU-unique
computation, measured energy advantage or emergent strategy.

## Circuit and scope

Six sequential fixed/learning FNP3 groups: raw key/history decoder, fixed admission
manager, always-updating bank with read-only forwarding helpers, fixed native
bridge, protected learning bank with read-only helpers, fixed output/history relay.
Each bank has eight plastic records, four for each binary outcome. All remaining
records are fixed helpers with unreachable learning threshold 32. Native class
competition chooses the record; outcome labels are actual consequences, not keys.
Native manager refuses a teacher input by sending an all-zero event vector to the
protected bank. This is data-path eligibility, not rewriting a learning register.
Queries still reach the protected bank regardless of admission.

Host supplies only current four raw key bits, a uniform query/teacher phase, and
the actual binary outcome after the prediction. The previous key comes directly
from the preceding query's native output buffer. Each teacher reuses its query
input pointer with phase changed; it does not advance history twice. All banks
share the same host-paced global query/teacher mode. This is not free-running
operation or self-generated observations. Diagnostics can read results/RAM but
cannot repair weights, calculate acting history, or select a bank or record.

## Gates fixed before any physical launch

1. Own-source CPU screen and compiler/virtual graph. Preserve rejected designs.
2. First seed short gate sequence: complete outputs and both RAMs replay exactly;
   rejected teacher leaves protected RAM unchanged; accepted teacher changes it;
   queries leave both RAMs unchanged; fixed RAM/helpers never change. Repeat under
   always-open and always-closed causal policies. Stop if any exact check fails.
3. First seed initial useful-context training; require correct read-only recall.
4. First seed pressure: ten nonconsecutive distractor keys with known outcomes
   compete against eight records, then four new useful repeating keys. Return to
   the two original useful keys and four new ones, with no teacher during probes.
   Compare native admission, same protected bank always-open, and trained-frozen.
5. Only after complete raw inspection, remaining four initializations and fresh
   sealed ordering. Report every cold prediction, missing/ambiguous response and
   transition separately. No adaptive seed/label selection or relabeling failures.

Native selective-writing mechanism success alone is not the promised next major
X milestone. Useful prediction plus adaptation/retention and causal controls are
required, with the designed policy honestly stated. A learned management policy
and efficiency under streaming load remain further gates. No X publishing here.

Every physical launch requires a new bounded authority, source/fixture hash
freeze, free device, exclusive lock, saved raw packets/inputs/both RAMs, finite
events and owned-process deadline. Failures stop expansion until a prospective
repair and remain archived. Licensed runtime and program images stay private.
