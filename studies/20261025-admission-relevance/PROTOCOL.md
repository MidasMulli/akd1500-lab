# Repetition versus useful recall: software preflight

Frozen before execution, October 25, 2026 UTC. This is a bounded software screen
of the existing circuit, not a new hardware experiment or a learned utility policy.
The previous physical studies remain closed. Physical sessions admitted here: zero.

## Question and inherited circuit

Can the qualified recent-key admission rule preserve future query coverage when
irrelevant observations repeat and later queried observations arrive spaced apart?
Keep the published twelve-key representation, outcome table, eight-record banks,
learning parameters and five initialization seeds. Only the observation schedule
changes. Actual outcome labels arrive after each prediction; held-out queries have
no consequence-bank teaching. The manager continues learning recency on queries.

The future query distribution defines this screen's narrow notion of useful recall.
Future reuse is not supplied to the actor. This is a counterexample screen of an
engineered repetition heuristic, not evidence that relevance can be learned from
arbitrary unobservable future choices. A subsequent policy study needs observable
outcome/error feedback and an explicit predictive objective.

## Sealed schedules

1. `original`: exact published held-out schedule, including the original sealed
   96-query ordering. This checks that the replay still reproduces qualified results.
2. `repeated_noise_spaced_signal`: bootstrap old keys 0/1; present each distractor
   2..7 sixteen consecutive times; teach later keys 8..11 eight times each, with
   each presentation separated by a pair of distractor observations. Then query
   old and later keys, including the same sealed 96-query ordering.
3. `repeated_noise_repeated_signal`: same bootstrap and repeated distractors, then
   sixteen consecutive presentations of each later key. This separates a blocked
   repetition test from exhausted capacity without reclamation.

Future test keys are identical in all schedules. Distractors are not inherently
meaningless; they simply are not queried by this sealed evaluation suffix. No
importance or future-use flag is an input to a learner. This tiny keyed task is
not a demonstration on natural sensory data or a complete memory manager.

## Next physical and strategic gates (not admitted by this preflight)

1. Qualify a native comparator receiving the prior prediction and later actual
   outcome. Check correct, incorrect, absent and ambiguous prediction cases, all
   input/output bits and learning RAM. Outcomes are external; prediction-error and
   admission decisions must be computed by the native circuit.
2. Test whether that feedback changes future admission through learned state.
   Identify the native policy state and credit path explicitly. A host importance
   label, record choice or weight repair does not qualify. A fixed error criterion
   must be described as designed; a learned management objective is not assumed.
3. Demonstrate lower future prediction error under a fixed memory budget against
   strong CPU and frozen/shuffled-feedback controls, including repeated distractors,
   rare consequential events, regime changes and returns to old conditions.
4. Qualify replacement and stale associations before claiming general memory
   management. Timing, calibrated energy and concurrent Nano load are later endpoints.

The useful application target is a resident experience memory for the Nano: preserve
exceptions that improve later predictions about a changing environment. The sealed
screen above only diagnoses the existing mechanism; it is not that application.
