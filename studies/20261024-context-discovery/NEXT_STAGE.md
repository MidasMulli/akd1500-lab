# Next executable series — designed, not yet physically admitted

The qualified component removes context-ID/record selection from the host. The
next capability is useful prediction conditioned on those native activations.
The following stages are gates, not claims of completed experiments.

1. Compiler/virtual integration: retain the existing fixed history/frontend and
   native context bank. Add a fixed bridge carrying learned record activations
   and the fixed raw-history basis into a downstream native consequence bank.
   Reserve fixed helper records there to keep the native raw-history output path.
   Different outcome labels may select consequence classes; they must never encode
   context IDs. No host readout-to-record lookup or weight repair in acting code.
   Preserve every failed route/mapping candidate before trying a new source.
2. Qualify the exact resident banks and per-bank mode transitions against full
   RAM readbacks. Single-class context learning and multi-class consequence
   learning have different no-label semantics. Teach raw histories first, then
   freeze that bank while measuring downstream prediction. This is staged bank
   learning, not a claim that independent learning clocks run simultaneously.
3. Prediction before feedback: the host streams only raw symbols. Capture each
   prediction before the next observed outcome exists. When that outcome arrives,
   teach the preceding native input buffer by pointer, with sufficient distinct
   buffers to prevent overwrite. Do not advance history twice for one observation.
   Verify every query/teacher descriptor's causal source, output, bank state and
   fixed-helper memory. External labels are actual outcomes, not planner commands.
4. Begin with four known contexts and admit twelve previously untrained contexts
   under one sealed deterministic generative stream. Require improved prospective
   next-symbol prediction, exact retention of previously learned outcomes, a fresh
   held-out ordering compatible with that generator, trained-then-frozen control,
   and strong raw-symbol CPU sequence predictor. Do not use a uniformly random
   suffix to claim predictable future bits: the present study tests recognition,
   not prediction. Keep boundary/transient events in reported denominators.
5. Only after that succeeds, separately test outcome reversal. Positive class-
   restricted learning can leave an old wrong-class record active while learning
   a new correct-class record. Native allocation/retention success does not prove
   erasure, negative feedback or unlearning. Resolve that directly with matched
   probes before promising recurring autonomous adaptation. Never hide ambiguity
   behind a CPU arbitration rule or host-selected neuron ID.
6. A useful substrate demonstration remains another gate: a representative
   streaming workload, strong concurrent CPU control, measured host traffic,
   service latency and calibrated power. Recognition accuracy on sixteen fixed
   histories cannot establish a neuromorphic efficiency advantage.

Choose finite seeds, stage counts, event ceilings and a new authority/cutoff before
physical admission. Keep the current study closed. No X post until the complete
capability, usefulness and its claim boundary are stronger than the current thread.
