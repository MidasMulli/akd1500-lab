# Native write selection — bounded results, 27 October 2026

The successful new mechanism is a learned native policy redirecting which memory neuron changes while the memory teaching label stays zero. This is a controlled primitive for memory management. It is not an autonomous allocator, a new learning rule, an exclusive CPU-inexpressible operation, or a novelty-priority claim.

## Measured

- Image-circuit support: algebraic compression reduced the mapped footprint from seven to six FNP3s. One fresh 882-forward support stream passed every returned output, complete learning RAM, and four fixed RAM packets. All 68 support recall probes passed. The spare FNP3 is (3,3,0). This is a support qualification; the full held image campaign was not repeated on the fused graph.
- Write-selection graph: four FNP3s, two learning banks, one pass. Eight memory neurons share a single teaching class. Two generic record anchors are selectable; six other records stay unchanged. The host sends input, policy supervision, static learning-role clocks and memory teacher 0. During a content write the host does not compute or send the destination, and it never patches connection RAM between forwards. Earlier external policy teaching does specify the desired A/B routing rule; that rule is not autonomously discovered.
- Primary native: 7/7 recall probes and six correctly targeted connection-edit events. The identical A/value-1 input goes to record 0 before the policy reversal and record 1 afterward.
- Matched policy counterfactual: memory RAM immediately before the write is byte-identical across native and policy-frozen runs, as are the input and memory teacher. Native changes record 1; the frozen policy changes record 0. Fixed routing packets are identical and unchanged.
- Controls: policy frozen 5/7 recall; route suppressed 3/7; forced record-0 route 4/7; memory frozen 3/7. All raw numerical/state audits pass. These are intentionally impaired controls, not execution failures.
- Held stream orders 27102712/13, using the prospectively fixed second initialization 27102712: 97/97 recall each, 61 and 44 actual content-edit events. Every changed record was the intended record; six untargeted records stayed unchanged. Primary plus held native recall: 201/201. These are three stream orders and two initializations, not three independent initializations.
- Exact-rule scalar/compiled CPU and an independent task-level dictionary CPU control also reproduce recall. No timing, power or contention comparison was run here.

## Derived evidence

The image readout/guard fusion uses a single-selected-record activation invariant. Fifty local algebra cases passed; the invariant holds on 22,554 archived R4 intermediate activation rows. Those activations were computed by the prior exact RAM mirror, not sampled as electrical spikes. The fresh fused silicon support run independently verifies end-to-end returned outputs and full RAM on its 882 rows.

Figures show captured weight-mask bits and returned pre-update potentials. Stored-value bits are decoded from captured RAM. Playback timing is editorial. The two displayed arms are separate matched sessions on the same physical card.

## Preserved failures

Four physical mixed-FNP/CNP attempts did not qualify. The first stopped before an enqueue because the all-CNP endpoint was sparse rather than the required raw dense output. The next three stopped after five forwards at the same missing policy response (output 451). Preserving the four-bit comparison boundary did not repair it. The requested guard-precision change produced a byte-identical programme/stream to the earlier candidate; that extra five-forward physical rerun was redundant and adds no independent precision evidence. A duplicate-condition launch guard was subsequently added to the new selector launcher; it includes per-bank parameter packets as well as programme and stream bytes. The cause remains unlocalized; these tests do not establish that the chip cannot route between those NP types. No capacity or scientific-success claim is made from their software simulations.

An uncompressed fused matrix requested forbidden FNP2 resources and was rejected before device access. Removing zero output columns and folding expansion into the raw formatter repaired the footprint without changing the tested functions. Two command/audit-path errors failed before device access and are preserved separately.

## Limits and closeout

Twelve owned physical sessions, 4,949 reserved forwards, 1,436 observed forwards: 1,421 from eight successful cells and 15 from three failed cells; the remaining failed session made no forward. Eight bounded source qualifications, zero encoder fits. The source-only cap was prospectively amended from six to eight for engineering repairs; physical/forward/deadline caps were unchanged. The campaign is closed and the card released. Existing console services and delegated Tab work were not touched. No GitHub or X publication occurred.

The memory values are binary and the two selectable anchors are preassigned. Policy mappings are externally taught. This is native destination selection, not self-discovered retention, arbitrary allocation, camera understanding, or an autonomous always-running network. CPU verification executes alongside the evidence actor but does not supply its destination or learned weights.

## Next frontier target

A resident memory lifecycle controller: admit a genuinely new key, select storage without a host-supplied record identity, protect useful old memories under pressure, and reclaim capacity through native connection changes. Demonstrate a useful stream and stable recall after policy changes. The current result establishes one necessary write-selection primitive; it does not complete that target. See NEXT_EXECUTABLE.md.
