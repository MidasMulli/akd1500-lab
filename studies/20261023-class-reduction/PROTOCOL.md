# Native threshold bank followed by a fixed class-support reducer

Prospective follow-on after the independently verified compact-output study.
The same learner's binary responses feed a fixed on-chip sum over each of two
class groups. Output is two integer counts, not probabilities, class argmax,
learned search or an image-recognition result. This changes the output contract
while preserving the complete tested learning update.

First compile paired mask/reduced models for 128/8 and 512/512. Reuse the earlier
validated ProgramInfo codec and intermediate-learning assembly pattern. Reject
FNP2, multi-pass, unfamiliar register differences, changed weights, or changed
inference tracks. The compiler's inference configuration remains intact; only
reviewed learning-mode metadata is restored. Virtual outputs must equal an
independent matrix/threshold/group-sum calculation.

Hardware gates: 16-sample small pair; independent recount and cross-contract
learned-field equality. Then 64-sample large pair, with the same checks. Only
after both pass, three interleaved 256-sample serial timing pairs. Ten physical
programming sessions maximum, 50,000 forwards and 180 seconds per process.
No speculative expansion after an unexplained mismatch. Own cleanup only.
The new study has its own stricter clock in local AUTHORITY.json.

Every reduced output must equal the sum of threshold responses in the relevant
group from an otherwise matched baseline stream. Entire learned RAM must match
the independent Python selector model. A fixed downstream layer is programmed
by us; it is not a newly discovered learning mechanism. No claims of max chip
utilization, autonomous execution, application accuracy, or energy advantage.

Timing includes inputs, submission, busy completion polling, and useful output
readback. Compilation, programming, RAM audits and verification are outside.
Compare to an optimized CPU popcount implementation of the same two-count
contract. Report this separately from the earlier richer output contracts.
