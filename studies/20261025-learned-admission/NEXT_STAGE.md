# Next gates after the native coordination milestone

The current circuit learns controller **state**, not its objective. Do not call
another hand-designed gate an emergent strategy or present a larger synthetic
key table as an efficiency result.

1. Challenge admission usefulness before increasing complexity. Seal streams
   where distractors repeat consecutively and useful observations arrive singly;
   report expected losses of the current heuristic. Evaluate changing relevance,
   class imbalance, partial cues, long gaps and switched outcome mappings with
   explicit missing/ambiguous/wrong predictions. The present pristine keyed task
   does not qualify any of those regimes.
2. Test a controller that changes its admission policy from grounded downstream
   utility/error feedback. Define actual costs and rewards, the credit path and
   which native state stores the policy. No host-computed importance tags, policy
   decisions or record repair may masquerade as native learning. Start with the
   smallest causal circuit; retain frozen/shuffled-feedback and strong CPU policies.
3. Independently qualify eviction/reuse and stale downstream associations under
   true capacity pressure. Presently retained old records are never reclaimed;
   protected spare capacity is not a general memory-management system.
4. Measure a representative PCIe streaming workload against tuned CPU controls.
   Remove per-event diagnostic RAM reads only after qualification, prove identical
   behavior, measure host traffic, service latency and calibrated electrical
   energy under concurrent Nano load. Seven sequential NPUs and correct predictions
   alone do not demonstrate parallel execution, whole-chip limits or an advantage.
5. Keep arbitrary reversal, resumed learning after restore, power-loss durability
   and indefinite host-quiet scheduling separate. Do not infer these from the
   finite native output/permission feedback path.

Each future physical series needs new prospective finite admission. Both current
studies are closed. This document is a design direction, not a hardware result or
a launch order that overrides future operator scope.
